# Jonah Pinon, engineering portfolio

A static site generated by Python. Each project and publication is a Markdown file, so adding work means writing a file and pushing it. GitHub Actions runs `build.py` and publishes the result to GitHub Pages.

Live address once deployed: `https://blu3jdev-byte.github.io/Portfolio/`

## Run it on your computer

You need Python 3.10 or newer.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python build.py serve              # live preview at http://localhost:8000/
```

`serve` rebuilds the site whenever you save a content file, template, stylesheet, or `config.py`. Refresh the browser to see the change.

`python build.py` (no arguments) writes the finished site to `dist/`. That is the folder GitHub publishes.

## How the project is organized

| Path | What it holds |
|---|---|
| `build.py` | The generator. Reads content, validates it, renders templates, copies static files. |
| `config.py` | Your name, intro line, links, accolades, and the site address. |
| `content/projects/*.md` | One file per project. |
| `content/publications/*.md` | One file per paper. |
| `templates/*.html` | Jinja2 page templates (`base`, `index`, `projects`, `project`, `publications`, `404`) and reusable pieces (`_macros.html`, `_beam.html`). |
| `public/` | Copied to the site as-is: `css/global.css`, images, paper PDFs, videos, the favicon. |
| `.github/workflows/deploy.yml` | Builds and publishes on every push to `main`. |

## Add a project

1. Copy `content/projects/_TEMPLATE.md` to a new file, for example `content/projects/heat-exchanger-redesign.md`.
2. Fill in the header block (title, summary, date, tools) and write the body under the headings: Problem statement, Approach, Solution, Results.
3. Run `python build.py serve` to preview it, then commit and push. The site updates in about a minute.

Set `draft: true` in the header to hide a project while you work on it. Set `featured: true` to show it first on the home page.

If a header field is missing, misspelled, or the wrong type, the build stops with a message naming the file and the field.

## Add images

1. Resize the image first. About 1600 px wide is plenty, and JPG or WebP keeps files small.
2. Put it in `public/images/<project-name>/`.
3. Show it in one of three ways:
   - **Cover image:** set `cover:` (and `cover_alt:`) in the header.
   - **Gallery:** add entries under `gallery:` in the header. Captions are numbered automatically (Figure 1, Figure 2, and so on).
   - **Inside the text:** `![Describe the image](/images/<project-name>/figure.jpg)`

## Add videos

Upload the video to YouTube (unlisted is fine) or Vimeo, then add the link under `videos:` in the project header. The site embeds it.

Avoid committing large video files. GitHub rejects files over 100 MB, and big files slow every future clone of the repository. A short clip under about 20 MB can go in `public/videos/` and be referenced as `/videos/clip.mp4`.

## Add a paper

1. Put the PDF in `public/papers/`.
2. Copy `content/publications/iac-2025-lunar-power.md` to a new file and edit the header: title, authors, venue, year, and `pdf: /papers/your-paper.pdf`. You can also set `doi:` and `abstract_url:`.
3. Paste the abstract into the body of the file. The site shows it behind a "Read the abstract" toggle.
4. To show the paper on a project page, add its file name (without `.md`) under `papers:` in the project header.

Publications appear on the home page and on the Publications page, newest first.

## Equations, tables, and code

Write equations in LaTeX between dollar signs: `$\sigma = Mc/I$` inline, or a block between `$$` lines. `build.py` converts them to MathML while building, so the finished site needs no JavaScript and no internet connection for equations. If an equation can't be converted, the build stops and shows it.

Standard Markdown tables and fenced code blocks (with syntax colors) also work.

## Change the intro text and links

Edit `config.py`. Use `HOME_PROJECT_COUNT` to control how many projects the home page shows.

## Change the look

All styling is in `public/css/global.css`. The colors are the variables at the top of the file. The page structure is in `templates/`.

## Publish on GitHub Pages

One-time setup:

1. Push this project to the `main` branch of the repository.
2. In the repository, open **Settings, then Pages**, and set **Source** to **GitHub Actions**.

After that, every push to `main` rebuilds and publishes the site.

## Use a custom domain later

In `config.py`, set `SITE_URL` to your domain and `BASE_PATH` to `""`. Then add the domain under **Settings, then Pages**.

## Placeholders to replace

- `content/projects/meen-305-beam-optimization.md`: the date is a placeholder, and the sections in italics are prompts to replace with your own text and numbers.
- `content/publications/iac-2025-lunar-power.md`: confirm the title, authors, and venue against the published paper.
- `config.py`: the intro line is a starting point. Edit it to say what you want.
